# /init — set up this project (rules/setup.md S1)

1. Init asks no setting. Settings live only in Configure (S1); init writes no settings file. An old repo or machine settings file is moved into Configure once by the script, which says each move.
2. Run `${CLAUDE_PLUGIN_ROOT}/bin/agent-init.sh` on the current project. Show its output unchanged, including the permissions block and the skip-warning line (new panes stop on the bypass warning screen). Never write `~/.claude/settings.json`: the human adds `"skipDangerousModePermissionPrompt": true` there himself. The agent never edits that file by hand.
3. Ask the human: "Add these permissions to .claude/settings.json for you? (yes/no)". Yes -> run `${CLAUDE_PLUGIN_ROOT}/bin/agent-init.sh --add-permissions` and show its output (it merges into the top-level `permissions.allow`, keeps every other key, and refuses invalid JSON without writing; never hand-edit that file). No -> say a plugin cannot add permission rules by itself, so he pastes the printed block into this project's `.claude/settings.json` himself.
4. Ask the human: "Use auto-pipeline in all your repos, or only selected ones? (all/selected)". all -> run `${CLAUDE_PLUGIN_ROOT}/bin/agent-init.sh --scope all` (or change nothing if it is already on everywhere). selected -> ask which repos (default: this one; use the repos the human names, or, when `${CLAUDE_PLUGIN_ROOT}/bin/agent-runtime.sh kind` says orca, `orca repo list --json` to offer a list), then run `${CLAUDE_PLUGIN_ROOT}/bin/agent-init.sh --scope selected <repo path>...` and show its output unchanged. It turns the plugin on in each chosen repo's `.claude/settings.json` and off in the user settings file (backup first). Never hand-edit those files.
5. Tell the human: a cloud session (claude.ai/code) has no `/plugin` command at all, so the only way this plugin reaches a cloud session is the repo's own committed `.claude/settings.json`.
6. Ask the human one short question: install the `agent-city` command in `~/.local/bin`, so `agent-city start` works in any terminal, from any folder? On a yes, run `${CLAUDE_PLUGIN_ROOT}/bin/agent-city.sh install-shim` and show its output unchanged (including the PATH hint line, if it prints one). On anything else, skip it; the human can run the same command later.
7. Init also writes `agent_repo.conf` (this repo's facts: core paths, guard tests, test commands, edges, real-data access) when it is missing, or adds only the keys it lacks and never changes a set value; its output shows one line per key. Read the new file. Turn each `# fix:` line that names a real edge case of this repo into an `edge=` line with `${CLAUDE_PLUGIN_ROOT}/bin/agent-file.sh edge add "<text>"`, then commit the file. A human may edit it, never has to.
8. Init also creates the working branch (ap-main-<name>, per person, stored once per clone) from the production branch, pushes it, and switches the main checkout to it (one line each); show those lines unchanged. A repo that already uses the plugin: init only creates the branch; the main manager switches the checkout at a quiet point.
9. End with these plain lines, in the human's language: settings are shown with `/auto-pipeline:settings` and changed in /plugin -> Installed -> auto-pipeline -> Configure; the main commands are `/auto-pipeline:todo` (see all open tasks) and `/auto-pipeline:question` (answer the agents' questions).
